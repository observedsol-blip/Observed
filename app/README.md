# Observed — app skeleton (mock data only)

An Expo SDK 54 / React Native 0.81.5 TypeScript skeleton for the three areas
**Today · Result · Record**, built to make the layout, type and the 21-tick scale
real enough to judge on a device. It talks to nothing.

## What is mocked

Everything. `src/mock.ts` is the single data module; screens hold local React
state and nothing else.

- No network calls of any kind. No `fetch`, no RPC, no Pyth, no explorer.
- No wallet, no Mobile Wallet Adapter, no `@solana/*` package is installed.
- No clock. Every time in the UI is a fixed string; nothing reads `Date.now()`.
- All numbers come from `docs/03-SCREEN-MAP.md` §Beispielzahlen:
  round 42 · 17 SEP today, reading of round 41 · 16 SEP, reference $150.00 →
  threshold $151.50, outcome **No** at $149.82, you 40 %, crowd 64,
  63 revealed of 71, Brier 0.160, Record 0.313,
  **9 commits · 8 reveals · 1 missing · 9 scored**,
  calibration "Unlocks after 21 revealed rounds · you're at 8".
- The nine past rounds in `pastRounds` are consistent with that record: the eight
  revealed Brier scores sum to 1.8125, the missing round counts as 0.250, and
  2.8125 / 9 = 0.313 (missing = 1.000 since 18.09.2026).
- Explorer links and transaction signatures are inert text.

## What is intentionally missing

- **Wallet / chain.** No seed vault, no approval, no commit or reveal
  transaction, no Genesis Token check. "Seal today" only flips local state.
- **The seal moment.** `src/components/SealMoment.tsx` exists, exports a
  component that returns `null`, and carries a comment saying the concept
  decision is open. There is **no animation anywhere in this app** — no
  `Animated`, no Reanimated. The strike on Result ("pending" struck through,
  "observed" set above it in pencil) is rendered statically by
  `src/components/StrikeMoment.tsx` so that nothing pre-empts that decision.
- **Screens not in scope here:** Onboarding (03 §1), Round Detail (§5),
  Publication as its own screen (§6 appears only as a line in Settings), Push
  (§8), error states (§9), the share card (§10) and the Android widget.

## The early read on Record — copy not yet in 03

**This is an owner addition and the copy is not in `docs/03-SCREEN-MAP.md`.**
03 §4 only locks the calibration curve until 21 revealed rounds. From **10**
revealed rounds onward, Record now also shows a provisional finding above that
lock:

```
Leaning hot · 12 revealed · ±14 pts
Unlocks after 21 revealed rounds · you're at 12
```

Rules it follows:

- `Leaning hot` = overconfident, `Leaning cold` = underconfident,
  `Leaning true` = inside the band. "True" is a position on the scale, not praise.
- The sample size and the band are **always** shown. There is never a verdict —
  the line states a leaning, its n, and its uncertainty, and stops.
- The calibration curve itself stays locked until 21 revealed rounds. The lock
  line is kept underneath, unchanged.
- Below 10 revealed rounds nothing changes: only the lock line, as 03 has it.

The leaning is **derived, not asserted** (`leaningOf()` in `src/mock.ts`): it is
the gap between the average probability given and how often Yes actually
happened, compared against the band. In the mock dataset the average is 65 and
Yes happened 50 % of the time, a gap of +15 points against a ±14 band — hence
"hot". Thresholds live in `EARLY_READ_MIN_REVEALED` (10),
`CALIBRATION_MIN_REVEALED` (21) and `EARLY_READ_BAND_PTS` (14).

The dataset is reachable from the Settings mock picker as **"Record · early read
at 12 revealed"** (13 commits · 12 reveals · 1 missing). The default state is
still the 8-revealed lock from 03 §Beispielzahlen.

## Fonts — what was used and why

| Role | Family | Package | Files bundled |
| --- | --- | --- | --- |
| Question, reading sentence, wordmark | Literata | `@expo-google-fonts/literata@0.4.3` | `400Regular/Literata_400Regular.ttf`, `600SemiBold/Literata_600SemiBold.ttf` |
| Controls, labels, **and all probability / Brier figures** | IBM Plex Sans | `@expo-google-fonts/ibm-plex-sans@0.4.1` | `400Regular/IBMPlexSans_400Regular.ttf`, `500Medium/IBMPlexSans_500Medium.ttf` |
| Ticks, times, prices, feed ids, signatures | IBM Plex Mono | `@expo-google-fonts/ibm-plex-mono@0.4.1` | `400Regular/IBMPlexMono_400Regular.ttf`, `500Medium/IBMPlexMono_500Medium.ttf` |

Note the split in the second and third rows — see "The marked zero" below.

Loaded with `useFonts` from `expo-font` in `src/fonts.ts`; the app renders a bare
ground colour until all six are ready, so there is no system-font flash.

### The Android variable-font finding

Variable-font cuts have failed to render on Android in this project before, so
the first thing checked was what these packages actually ship.

**All three packages ship static, per-weight TTFs only. None of them contains a
variable cut.** Verified against the installed tree:

```
$ find node_modules/@expo-google-fonts -iname '*variable*' -o -iname '*_wght*'
(no output)

$ ls node_modules/@expo-google-fonts/literata
200ExtraLight  300Light  400Regular  500Medium  600SemiBold  700Bold
800ExtraBold   900Black   … (+ matching _Italic dirs)   index.js  useFonts.js
```

Literata ships 16 TTFs (8 weights × roman/italic), IBM Plex Sans and Plex Mono
14 each (7 × 2). Each weight sits in its own directory with its own `index.js`
that `require`s exactly one `.ttf`. So the failure mode is avoided by
construction — there is no variable file to pick by accident, and no
`fontWeight` interpolation is relied on: every weight is addressed by its own
family name (`Literata_600SemiBold`, not `Literata` + `fontWeight: '600'`).
That is also why `tokens.ts` names full family strings.

**Import the per-weight subpaths, not the package index.** `src/fonts.ts` does

```ts
import { Literata_400Regular } from '@expo-google-fonts/literata/400Regular';
```

rather than `from '@expo-google-fonts/literata'`. The package index re-exports
every cut, which would pull all 16 (resp. 14) TTFs into the bundle. With the
subpath imports the release APK carries exactly the six files listed above —
confirmed with `unzip -l app-release.apk | grep -i '\.ttf'` after
`assembleRelease`, which prints six entries and no more:

```
   218268  res/MF.ttf     255252  res/Nr.ttf     255604  res/RM.ttf
   218236  res/SR.ttf     134956  res/qX.ttf     133796  res/rV.ttf
```

They land under `res/` rather than `assets/`: the `expo-font` config plugin
embeds the fonts as Android resources at build time, and AAPT shortens the
resource names during `optimizeReleaseResources`. `useFonts` resolves them
either way. That the release build succeeds and exactly those six files are
present is the proof that fonts and assets bundle correctly.

### The marked zero — why large digits are Plex Sans

The design brief forbids a slashed zero. A web prototype had hit exactly that
with IBM Plex Mono at large sizes, so the shipped TTFs were inspected directly.

**Finding: IBM Plex Mono's default `zero` is a marked zero, and the family ships
no unmarked alternative.** Evidence from the fonts extracted out of the built
APK (`unzip -o app-release.apk 'res/*.ttf'`, then fontTools):

```
IBM Plex Mono Regular   zero  contours=3  pts/contour=[20, 22, 14]   alts: zero.alt01(3) zero.alt02(composite)
IBM Plex Mono Medium    zero  contours=3  pts/contour=[20, 18, 14]   alts: zero.alt01(3) zero.alt02(composite)
IBM Plex Sans Regular   zero  contours=2  pts/contour=[16, 18]       alts: zero.alt01(3) zero.alt02(3)
IBM Plex Sans Medium    zero  contours=2  pts/contour=[16, 18]       alts: zero.alt01(3) zero.alt02(3)
Literata Regular        zero  contours=2
Literata SemiBold       zero  contours=2
```

A plain oval zero is two contours: outer and counter. Plex Mono's is **three** —
the extra 14-point contour is the mark, and rendering the digits at their real
sizes with Pillow confirms it: in Plex Mono the zero carries a **centre dot**,
not a diagonal slash. Strictly speaking it is a dotted zero rather than a
slashed one, but it is the same marked-zero family the brief rules out, and at
64 sp it is unmissable — so it was treated as forbidden. *If the owner reads the
rule narrowly as "diagonal slash only", this decision can be reversed by
pointing `font.figures` back at Plex Mono in `tokens.ts`.*

Crucially, **no OpenType feature can rescue it**: Plex Mono's `zero.alt01` also
has three contours and `zero.alt02` is a composite — there is no two-contour
zero anywhere in the font. (In Plex Sans it is the other way round: the clean
zero is the default and the marked ones are the opt-in alternates.)

**What changed.** Large hero digits, the Brier values, the Record counts, the
baselines and the `Crowd 64 · You 40` line now render in **IBM Plex Sans**.
Plex Sans loses nothing in alignment: its digits are already tabular — every
advance is 600 units, checked across `0`–`9` in both weights. Plex Mono is kept
for scale tick labels, times, prices, feed ids and transaction signatures, per
the owner's instruction; the tick labels and the evidence block therefore still
show Plex Mono's dotted zero, which is deliberate.

Reproduce:

```bash
cd /tmp && mkdir -p fc/apk && cd fc/apk
unzip -o -q ~/Downloads/observed-app-skeleton.apk 'res/*.ttf'
python3 - <<'PY'
import glob
from fontTools.ttLib import TTFont
for f in sorted(glob.glob('res/*.ttf')):
    ft = TTFont(f); g = ft['glyf'][ft.getBestCmap()[ord('0')]]; g.expand(ft['glyf'])
    print(ft['name'].getDebugName(4), 'zero contours =', g.numberOfContours)
PY
```

## Design tokens

`src/tokens.ts` is the only place colour, type and spacing are defined.

| Token | Value |
| --- | --- |
| ground | `#1C1F1D` |
| ink | `#E8E0D4` |
| meta | `#8B8680` |
| pencil | `#5B7CFA` |
| hairline | ink at 18 % — `rgba(232, 224, 212, 0.18)` |

No radii, no shadows, no gradients, no elevation, no texture on the ground.

**Divergence from `docs/04-DESIGN-BIBLE-BRIEF.md`:** that brief specifies pencil
blue `#3A6EA5`. The owner override `#5B7CFA` is used instead, and is what is in
`tokens.ts`. Everything else follows 04: pencil appears only on the user's own
value and cursor, the user's own bucket in the distribution, and the strike over
"pending" — never on an outcome, never on the CTA, which is ink on ground with a
hairline edge.

## The 21-tick scale

`src/components/Scale.tsx` is one component used twice. Both modes derive every
x-coordinate from the same `xFor()` function over the same `TICKS` array
(`0, 5, … 100`, 21 positions), so a value sits at the identical pixel in either
mode.

- `mode="input"` — `PanResponder` drag on a 56 dp row, snapping to the nearest
  of the 21 positions; `−5` / `+5` buttons are 64 × 48 dp; cursor in pencil;
  reachable with one thumb. TalkBack: `accessibilityRole="adjustable"` with
  increment/decrement actions and a spoken percent value.
- `mode="distribution"` — 21 bars at those same coordinates, crowd in graphite,
  the user's own bucket in pencil, mean as a vertical ink line.

## Copy

All UI strings are verbatim from `docs/03-SCREEN-MAP.md`. The words *closer*,
*streak*, *win*, *lose*, *approve transaction* and *reference natural
transaction* appear nowhere. Times are always given as UTC **and** local.
The missing-round penalty is worded as 03 words it in English — "missing counts
a full miss" and "1 missing (counts as a full miss)"; the German "1,000" form from the spec
prose is not UI copy and is not in the app.
